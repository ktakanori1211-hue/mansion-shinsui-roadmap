# 説明書（全部入りの版）

この版で何が入っていて、どう動くかを、画面ごとにまとめた説明書です。
この版は「削らない・薄めない」版で、見やすさの整理と削る作業は次の版で行います。

- 仕様（決めたこと）: [SPEC.md](../SPEC.md)
- 要件定義（ノート6つの中身を全部書き直したもの）: [REQUIREMENTS.md](REQUIREMENTS.md)
- アプリの中の「調べたこと」の段階: 同じ要件定義の全文と、137件の資料を読めます

## 1. 動かし方

```bash
python3 -m app.server
```

http://localhost:8000 を開きます。API キーがなくても、Claude を使う部分以外はすべて動きます。

画面の確認は、キーを読まない別のサーバーで行います（このリポジトリの決まり）。

```bash
HOME="$(mktemp -d)" PORT=8766 python3 -m app.server
```

テストは API を呼びません。

```bash
python3 -m unittest discover -s tests -t .
```

## 2. 画面の流れ

上のタブは、①場所、②建物、③資料、④費用、＋調べたこと の五つです。右上の「AIに相談する」は押したときだけ開きます。

### 最初の画面（住所を入れる前）

- 一言（「水が引いた翌朝、このマンションは何日で水が出るか」）と、三つの手順、住所の検索欄、架空の見本 A・B・C のボタンが出ます。
- 住所、マンション名、郵便番号、駅名、現在地、地図を押す、のどれでも場所を選べます。マンション名は、地図に名前がある所か、API キーがあるときに Web 検索で確かめられた所だけを候補にします。

### ① 場所

- **天気の場面カード（5枚）:** 台風、線状降水帯、上流の大雨、満潮、地震（津波）。浸水の8つのパターンを、どの場面で重なるかで束ねています。
  - この土地の地図の色（すぐ近くの色を含む）や凹みの形に当てはまるパターンの数で、カードが灰・橙・赤になります。
  - カードを押すと、地図の上で水が広がります。公的な地図に色がある所は深い区分から順に濃い青で、色がない所は標高から凹みに水がたまる様子を水色の「模式」で見せます。終わると地図の左下に、建物の前の深さと、②で確かめる入り道が出ます。
  - 「パターンと出典」を開くと、8つのパターンの内訳と出典の文が読めます。
- **地図:** 国のハザードマップ（洪水の計画規模・想定最大規模、内水、高潮、津波）を重ねられます。データが取れない所は斜線です。色別標高図と、水が来そうな側・電気室の扉の側を地図で押す道具は「地図で詳しく調べる」の中にあります。
- **土地の形:** ピンの周りの南北・東西の標高の図。周りの方が高い凹みでは、外からピンへ向かう矢印を出します。
- **立地の5項目:** 洪水、内水、高潮、敷地の高低差、市の浸水の記録を、リスクあり（確定）／未確認（調査が必要）／問題なし の三つに分けます。分からないことを危険とは出しません。

### ② 建物

- 見本以外では、図面を入れるか、近い建物の形（A・B・C）を選んでから、図面と3Dが出ます。
- **図面（CAD）:** 平面図、断面図（水の入り道）、系統図（電気と給水）をタブで切り替えます。押すと大きく開き、PDF と DXF も開けます。平面図には確かめる場所のピン（ア・イ・ウ・エ）が立ちます。
- **3D:** 水の位置（①道路・スロープ、②一番低い床、③盤や受電の箱の下端）と対策（止水板だけ、壁の穴を塞ぐ、盤を高くする）を切り替えると、止まる想定の設備が変わります。
- **止まる設備の数:** 住民が使えなくなる4つ（給水、エレベーター、廊下の照明、各戸の電気）を数えて大きく出します。見本の「止水板だけ」では、水の位置①で0、②で1、③で4です。各戸の電気は、止まる想定でないときは「建物側から分からない」と出し、数えません。
- ①で場面を押していれば、3Dの上に場面の名前と「この建物で確かめる入り道」が出ます。
- 建物の質問と書類（分かる所だけ）、何が止まるか、停電の連鎖と時間の流れの表も、この段階にあります。

### ③ 資料

- A4 の一枚（おもて・裏・別紙）、依頼メモ①②③、理事会の議題のたたき台、補助と手続きの順番のメモ。
- 印刷（PDF 保存）と、パスワードと期限つきの共有リンク（ブラウザの中で暗号にしてから置くので、サーバーは中身を読めません）。
- API キーがあるときは「Claude で読みやすく整える」が使えます（この版では API を呼んで確かめていません）。

### ④ 費用

- 対策を選ぶと、費用の桁、決める場、補助の計算の例が変わります。見積り額を入れると円で計算します。
- 「専門家に調査・見積もりを相談する」で、カルテ、手続きの段取り、依頼文の3つの文書を作ります。送るのは管理組合で、この道具からは送りません。

### ＋ 調べたこと（この版で足した段階）

- 本人が調べたノート6つ（なぜ・何を・市場とモデル・どう作るか・判定表・数字と出典）の中身を、新しい文で書き直した資料が137件あります。領域と言葉で絞り込めます。
- 各資料には「事実」「仮説」「決定」「機能」「注意」のラベル、出典、もとのノートの項目の番号が付いています。
- 項目の振り分けの表（アプリに既にある／資料として追加／機能として追加／仕様書だけ／入れない）、ノートに書かれた機能とアプリでの状態の表、入れなかった項目の理由ごとの数、要件定義の全文も、ここで読めます。
- 場所を選ばなくても読めます。印刷には入りません。

## 6. まだ決まっていないこと（本人の判断が要る）

電気保安の観点でのレビュー（Claude のサブエージェント）で、ノートとアプリで食い違った文を見ました。承認済みの文は変えていません。直すかどうかは本人が決めてください。

1. **主任技術者のいない建物で、免責の1行目に添える括弧書き**
   - 今のアプリの文（電気工事の業者の点検と測定の結果を見て管理組合が判断し、東京電力パワーグリッドに連絡する）の骨格の方が、実務に近いという意見でした。
   - ノートの文（東京電力パワーグリッドおよび電気工事業者が安全を確認して判断する）は不適切、という意見です。東京電力パワーグリッドはマンション側の安全を確かめず、電気工事業者には判断の権限がないためです。
   - 推奨の文：「（電気主任技術者を選任していない建物では、借室は東京電力パワーグリッドの確認を待ち、マンション側は電気工事の業者が点検・測定した結果を書面で受けて管理組合が判断する。どちらかが済むまで電気を戻さない）」
2. **3Dの画面の「水の位置は、立ち入ってよい高さではありません」の文**
   - 借室とマンション側の部屋を書き分けるべき、という意見でした。
   - 推奨の文：「水が引いても、借室（東京電力の変圧器の部屋）は東京電力パワーグリッド、マンション側の部屋は主任技術者（いない建物では電気工事業者）が安全を確かめて入ってよいと指示するまで、住民、理事、管理員は入りません。」
3. **「盤の下の端は主任技術者が月次点検の立会いで測ります」**
   - 月次点検は主任技術者が単独で行うのがふつうで、「立会い」は年次の停電点検の言い方なので、実務と合わないという意見でした。
   - 推奨の文：「床からの盤や箱の高さは未確認です。管理会社か電気工事の業者が巻き尺で測り、依頼メモに書きます。主任技術者がいる建物では、月次点検のときに高さの確認と記録を頼めます（契約の範囲は要確認）。」

4. **ほかの食い違い**
