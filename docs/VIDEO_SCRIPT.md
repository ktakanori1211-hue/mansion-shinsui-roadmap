# 3分動画の台本（下書き）

提出用のデモ動画の台本です。2026-11-07 の画面（1 場所 → 2 確かめる → 3 止まるもの → 4 渡す）を操作しながら、そのまま読める順に書いています。

2026-11-05 夜に、過去の受賞者の話（セッション第4弾）を受けて、機能の順ではなく「作者の物語」と「前と後の対比」の形に組みました。2026-11-07 に、画面1の掛け算・画面2の図面読み取り・画面3の対策の切り替え・画面4のA4縦1枚に合わせて場面を書き直しました。

## 組み立ての考え方

- **物語から入る。** 冒頭は機能ではなく、作者（電気主任技術者）が現場で見たことから始める。受賞者は口をそろえて「機能より、あなたの仕事がどれだけ大事かを見せる」「意外な人が作ったことが一番際立つ」と言っていた。
- **前と後の対比を一つ立てる。** 前：地図に色がない場所でも浸水は起きる。電気室への水の入り道は、だれの仕事にもなっていない。後：図面を読ませて3つ答えると、理事会で決められる対策と費用が、A4縦1枚になる。
- **見どころは1つの流れ。** 「掛け算で洗い出す」（画面1）→「図面を読んで、すべて入れる」（画面2）→「対策を切り替えると赤が緑になる」（画面3）→「A4縦1枚と1戸あたり」（画面4）。
- **一秒一秒に意味を持たせる。** 素材は3分より多く撮れるので、ナレーションのない間（ま）は画面の変化だけにする。
- **主役は WHY・WHAT のとおり。** 地図に色がなくても浅い水で止まる足元（水位①②③）と、理事会で決められる安い対策。ハザードマップの深さを主役にしない。避難の判断は自治体の地図と警戒レベルに任せる。

ナレーションは約900字です。1秒に5〜6字で読み、画面操作の間（ま）を入れて3分に収めます。画面はパソコンの幅（960px）で撮ると、画面1の2枚のカードと画面3の表が1画面に入ります。

## 撮るときの注意

- **作者の話（0:00・2:38）：** 立ち会った現場の場所・建物・深さ・時期は言わない。現場の写真も使わない（建物が特定されないように。要件 W2）。見本Aの建物を、作者の現場の例として紹介しない（要件 how-024 の特定回避）。

- **建物：** 架空の見本（見本A「うみかぜコート」）で撮る。実在の住所は映さない。検索欄に本物の住所を入れない。

## 撮影の手順

画面の録画は作者が行います（このリポジトリの作業では録画できません）。

1. **サーバーを起動する。** `python3 -m app.server` で 8000 を起動します。キーはホームのファイルから読みます。キーの欄やターミナルは映しません。
2. **幅を決める。** パソコンの幅（960px 以上）で撮ると、画面1の2枚のカードと画面3の表が1画面に入ります。スマホの幅（375px）で撮るなら、Chrome の開発者ツールの端末の表示にします。ブラウザの拡大は 100% にします。
3. **録画を始める。** macOS なら Command＋Shift＋5 で、ブラウザの画面の範囲だけを録ります。
4. **場面ごとに撮る。** 上の台本の順に、場面ごとに別の録画にすると撮り直しが楽です。場面を始める前にページを読み込み直すと、最初の状態に戻ります。
5. **作者の話を撮る。** 0:00 と 2:38 は、スマホで正面から撮るか、声だけを録って断面図の再生に重ねます。背景に住所や建物が分かるものを入れません。
6. **図面の読み取りの場面。** `web/samples/plan_a.png`・`section_a.png`・`system_a.png` を「図面の写真・PDFを選ぶ」で3枚同時に入れます。2026-11-07 に本物のキーで読んでいて、答えは手元の控え（`data/cache/`、公開しない）に残っています。同じ画像なら API を呼ばずに同じ答えがすぐ出ます。
   - 読み取りの結果：給水ポンプ室・電気室・借室とも「地下1階」。地上11階・地下1階。引込み 地中、高圧受電、盤 壁掛け、スロープあり、管路口あり、放流先 公共下水道。「すべて入れる（10件）」で全部入ります。
7. **チャットの場面。** 危ない質問は、AI を通さない固定の文になります。答えの下の「固定の文（AIを通していません）」まで映します。
8. **仕上げ。** 場面をつないで3分に収め、「足すと64%」「費用の目安」「補助の計算例」（映れば「断水8日・トイレ11日」も）の字幕と、最後の固定の免責を入れます。
