# 3分動画の台本（下書き）

提出用のデモ動画の台本です。2026-11-05 に1本にまとめた4つの画面で撮ります。

2026-11-06 に、画面の順番を「確かめる（画面2）→ 止まるもの（画面3）」に入れ替えたので、場面の順も入れ替えた。2026-11-05 夜に、過去の受賞者の話（セッション第4弾）を受けて、機能の順に並べた台本を「作者の物語」と「前と後の対比」の形に組み直しました。

## 組み立ての考え方

- **物語から入る。** 冒頭は機能ではなく、作者（電気主任技術者）が現場で見たことから始める。受賞者は口をそろえて「機能より、あなたの仕事がどれだけ大事かを見せる」「意外な人が作ったことが一番際立つ」と言っていた。
- **前と後の対比を一つ立てる。** 前：地図に色がない場所でも浸水は起きる。電気室への水の入り道は、だれの仕事にもなっていない。後：理事会で決められる安い手（壁の穴を塞ぐ）で、受電設備の「復旧に1年以上の場合も」の目安が消える。それでも給水の盤は残るので、確かめる場面（画面3）へつなぐ。
- **見どころは1つの流れ。** 「確かめると色が変わる」（画面2）→「その建物で、浅い水で何が止まるか」（画面3の再生と高さの目盛り）→「安い手で何が変わるか」（対策の切り替え）。
- **一秒一秒に意味を持たせる。** 素材は3分より多く撮れるので、ナレーションのない間（ま）は画面の変化だけにする。
- **主役は WHY・WHAT のとおり。** 地図に色がなくても浅い水で止まる足元（水の位置①②③）と、理事会で決められる安い対策。ハザードマップの深さを主役にしない。避難の判断は自治体の地図と警戒レベルに任せる。

ナレーションは約850字です（場面ごとに1秒あたり4〜5.5字）。1秒に5〜6字で読み、画面操作の間（ま）を入れて3分に収めます。画面はスマホの幅（375px）で撮ります。

## 撮るときの注意

- **作者の話（0:00・2:44）：** 立ち会った現場の場所・建物・深さ・時期は言わない。現場の写真も使わない（建物が特定されないように。要件 W2）。見本Aの建物を、作者の現場の例として紹介しない（要件 how-024 の特定回避）。
- **0:24 の数字：** 字幕に「ウェザーニューズ 2026年9月22日」と出典を付ける。千葉の8月の豪雨の数字は、この台本では使わない（見本Aが千葉市の町丁なので、作者の現場と結びつけて読まれないように）。
- **建物：** 架空の見本（見本A「うみかぜコート」）で撮る。実在の住所は映さない。
- **住んでいる階：** 見本Aは11階建てなので、住んでいる階は「8」で撮る。
- **答えの再現：** 見本Aで画面2の順に答えると、赤と緑の両方が出る（②「地下」→ 電気室が赤、③「2階以上」→ 借室が緑。未確認 3 → 2 → 1）。撮り直しても同じ結果になる（API を使わない）。
- **写真の読み取り：** 画面2の「図面の写真から読む」は、本物の API キーで1回だけ撮る。キーがないときは、見本の答えに「読み取りの結果ではありません」と出る。それを Claude が読んだ場面として使わない。
- **チャット：** 2:28 の危ない質問は、キーがあってもなくても固定の文になる（AI を通さない）。答えの下の「固定の文（AIを通していません）」まで映す。
- **APIキー：** 画面にもターミナルにも映さない。右上の「Claude」のボタンの欄も開かない。
- **保存の場面：** パスワードの欄は映さないか、ぼかす。リンクも映さない。
- **1年以上の目安：** 1:44 の「復旧に1年以上の場合も」には、「一般的な目安（建築設備技術者協会の報告書）。この建物の日数ではない」と字幕を付ける。
- **費用の目安：** 1:44 の「1か所5万円」には、「作者の実務の目安。見積りに置き換える」と字幕を付ける。
- **補助の計算例：** 2:10 の補助の計算には、「計算例。補助の条件（過去に浸水被害が発生した地域など）は市に確かめる」と字幕を付ける。見積り額は架空の値で撮る。
- **断水の日数：** 画面3の「武蔵小杉は断水8日・トイレ11日」が映る場合は、「ほかの建物の例（建築設備技術者協会の調査など）。この建物の日数ではない」と字幕を付ける。
- **再生の注意書き：** 1:22 の平面図の再生は、画面に出る「実際の浸水速度の予測ではなく、水が順番に入る仕組みの模式です。」が映るように撮る。
- **免責：** 最後に、画面の下の固定の免責の文をそのまま映す。言い換えも省略もしない。

## 撮影の手順

画面の録画は作者が行います（このリポジトリの作業では録画できません）。

1. **サーバーを起動する。** `python3 -m app.server` で 8000 を起動します。キーはホームのファイルから読みます。キーの欄やターミナルは映しません。
2. **スマホの幅にする。** Chrome の開発者ツールの端末の表示で、幅を 375px にします。ブラウザの拡大は 100% にします。
3. **録画を始める。** macOS なら Command＋Shift＋5 で、ブラウザの画面の範囲だけを録ります。
4. **場面ごとに撮る。** 上の台本の順に、場面ごとに別の録画にすると撮り直しが楽です。場面を始める前にページを読み込み直すと、最初の状態に戻ります。
5. **作者の話を撮る。** 0:00 と 2:44 は、スマホで正面から撮るか、声だけを録って平面図の再生に重ねます。背景に住所や建物が分かるものを入れません。
6. **写真の読み取りの場面。** 見本Aの平面図の画像（`web/samples/plan_a.png`）を「写真・PDFを選ぶ」で入れます。2026-11-05 に本物のキーで1回読み取っていて、その答えが手元の控え（`data/cache/`、公開しない）に残っています。同じ画像なら API を呼ばずに同じ答えがすぐ出るので、撮り直しても料金はかかりません。
   - 読み取りの結果：電気室・借室・ポンプ室とも「地下1階」。①〜③に「地下」を入れる候補が出ます。
7. **チャットの場面。** 危ない質問は、AI を通さない固定の文になります。答えの下の「固定の文（AIを通していません）」まで映します。
8. **仕上げ。** 場面をつないで3分に収め、「64%」「1年以上」「費用の桁」（映れば「断水8日・トイレ11日」も）の字幕と、最後の固定の免責を入れます。
