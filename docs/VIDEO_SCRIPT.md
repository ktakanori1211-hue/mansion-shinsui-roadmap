# 3分動画の台本

提出用のデモ動画の台本です。2026-11-07 夜の画面（1 場所 → 2 確かめる → 3 止まるもの → 4 渡す）を操作しながら、そのまま読める順に書いています。

## 組み立ての考え方

- **物語から入る。** 冒頭は機能ではなく、作者（電気主任技術者）が現場で見たことから始める。過去の受賞者は「機能より、あなたの仕事がどれだけ大事かを見せる」「意外な人が作ったことが一番際立つ」と言っていた（セッション第4弾）。第5弾の示唆「みなさんにしかできない課題解決を、持っているデータとナレッジで」も同じ。
- **前と後の対比を3つ。** ①地図に色がない場所でも浸水は起きる → 掛け算で洗い出せる（見本B → 見本A）。②図面は読めない → 3枚まとめて読んで「すべて入れる」で最優先の対策が変わる。③AI は危ないことも答えてしまう → 危ない質問は AI を通さず0秒で止め、安全な質問だけ電気主任技術者の規則で答えて図が光る。
- **一秒一秒に意味を持たせる。** ナレーションのない間（ま）は画面の変化だけにする。
- **主役は WHY・WHAT のとおり。** 地図に色がなくても浅い水で止まる足元と、理事会で決められる安い対策。避難の判断は自治体の地図と警戒レベルに任せる。

ナレーションは約880字。1秒に5〜6字で読み、操作の間（ま）を入れて3分に収めます。画面はパソコンの幅（960px 以上）で撮ると、画面1の2枚のカードと画面3の表が1画面に入ります。

## 撮るときの注意

- **作者の話（0:00・2:44）：** 立ち会った現場の場所・建物・深さ・時期は言わない。現場の写真も使わない（建物が特定されないように。要件 W2）。見本の建物を、作者の現場の例として紹介しない（要件 how-024 の特定回避）。

- **0:32 の見本B：** 国の地図の3項目は「色なし」ではなく「データなし」なので、ナレーションも結論の文も「色を確かめられない」と言う（「色がない」と言わない）。型に当たる根拠は地形分類（盛土地・埋立地）で、くぼ地ではない。
- **建物：** 架空の見本（見本B「たにとハイム」、見本A「うみかぜコート」）で撮る。実在の住所を検索欄に入れない。

## 撮影の手順

画面の録画は作者が行います（このリポジトリの作業では録画できません）。

1. **サーバーを起動する。** `python3 -m app.server` で 8000 を起動します。キーはホームのファイルから読みます。キーの欄やターミナルは映しません。
2. **幅を決める。** パソコンの幅（960px 以上）で撮ると、画面1の2枚のカードと画面3の表が1画面に入ります。ブラウザの拡大は 100% にします。
3. **キャッシュを温める。** 撮影の直前に、見本Aで3枚の図面を一度入れ、チャットで Q1 を一度聞いておきます（どちらも2回目は一瞬）。
4. **録画を始める。** macOS なら Command＋Shift＋5 で、ブラウザの画面の範囲だけを録ります。
5. **場面ごとに撮る。** 上の台本の順に、場面ごとに別の録画にすると撮り直しが楽です。場面を始める前にページを読み込み直すと、最初の状態に戻ります。見本B → 「別の場所を探す」 → 見本A は、同じ録画の中で続けて撮ります。
6. **作者の話を撮る。** 0:00 と 2:44 は、スマホで正面から撮るか、声だけを録って断面図の再生に重ねます。背景に住所や建物が分かるものを入れません。
7. **仕上げ。** 場面をつないで3分に収め、「足すと64%」「費用の目安」「補助の計算例」（映れば「断水8日・トイレ11日」も）の字幕と、最後の固定の免責を入れます。

## 提出前に動画を見返す（セッション5弾「安全に公開する」の最終確認）

アップロードする前に、できあがった動画を最初から最後まで止めずに見て、次の3つを確かめます。1つでも映っていたら撮り直します。

1. **有効な API キーが写り込んでいないか。** 右上「設定」の欄、ターミナル、ブラウザのアドレス欄、通知。
2. **他人の実データが表示されていないか。** 実在の建物の図面や点検報告書、番地まで入った住所、作者の自宅が分かる背景。見本 A・B・C と、公開情報だけで確かめられる建物名に限る。
3. **エラー画面に機密が出ていないか。** 赤いエラーの文、ターミナルのスタックトレース、`data/cache/` や `data/shares/` のパス。
