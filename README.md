# マンション浸水チェック

（リポジトリ名 mansion-shinsui-roadmap。旧称：マンション浸水ロードマップ）

浸水のあとに水と電気がどれだけ止まりうるかを、住所と手元の情報から整理し、理事会に出せるA4一枚を作るWebアプリです。Built with Claude: Japan 2026（2026-11-02〜11-08）の期間中に作りました。

## 解く課題

ハザードマップに色がないマンションでも、道路から数十cmの水が地下や1階の電気室・給水ポンプ室に入ると、全戸で断水し、エレベーターと共用部の電気が止まります。理事会の役員は電気の専門家ではないので、「自分の建物の機械室は何階か」「止めるには何をいくらで」「理事会で何を決めればよいか」が分からず、対策が進みません。このアプリは、住所と手元の図面から、止まる設備・優先する対策・費用と補助・本日決めることを、プログラムの決まりで整理して A4 一枚にします。使うのは理事会の役員と管理会社の担当者で、判断の最後は電気主任技術者と工事業者が行います。

画面は1本で、スマホの1列に4つの画面が並びます（2026-11-05 にメンターの助言を受けて一本化し、2026-11-07 までに今の形にしました）。

1. **場所**：住所・マンション名か、架空の見本を選びます。結論は「ハザードマップ（国の地図：川の洪水・高潮・内水）× 線状降水帯で浸かる型（国土地理院の地形分類・周囲50mの標高・国の内水の地図）」の2枚のカードで、両方に当たる／地図だけ／地図に色はないが浸かる型／どちらも当たらない／データ不足の5通りをプログラムの規則で出します。その下に、東西200mの標高の断面に建物と国の地図の深さの帯を重ねた2Dの図、折りたたみの「根拠の数値（判定と出典）」、住所の市区町村の補助（率・上限・条件の1行と計算例）を出します。建物名で検索したときは、Claude の Web 検索で地上・地下の階数を出典つきで探します。
2. **確かめる**：一文「機械室の階によって、浸水時に止まる設備が決まります」の下に、残りの数と3つの部屋の答えを並べます。図面（平面図・断面図・配置図・電気設備図・単線結線図・給排水設備図・外構図）を複数枚まとめて Claude に読ませ、部屋の階・階数・引込み（地中／架空）・受電（高圧／低圧）・給水ポンプ制御盤の置き方・排水の放流先・逆止弁・スロープ・換気口・管路口の候補を出します。各行の「入れる」か「すべて入れる」で答えに入り、「取り消す」で戻ります。3つの問い（給水ポンプ室・電気室・借室は図面で何階か）に答えると、その瞬間に「→ 地下：浸水すると全戸で断水（止まるおそれ）」の一行と、最優先の対策の1行が変わります。図面がない人は、見て答えられる3問が依頼メモに載ります。
3. **止まるもの**：建築CAD風の平面図・断面図（自分の図面を入れたときはその画像も）の上に、1「▶ 浸水シミュレーションを始める」、2「対策を切り替えて比べる」（対策なし（現状）／① 止水板＋壁の穴を塞ぐ／② さらに盤を高くする）、3「図を切り替える」の順に番号を振った操作と、左から右へ水が上がる水位のゲージ（① 道路 → ② 一番低い床 → ③ 機械の部屋。◀ ▶ か「▶ 浸水シミュレーションを始める」）を置きます。水は濃い青の面と動く波で描き、水位ごとに何が起きるかを1行で言い、対策を選ぶと図の中の止水板・埋めた穴・赤い×で「どこで止めたか」が見え、下に「✔ 止めた所」が並びます。部屋の札は赤「浸水・停止」から緑「止水・稼働」に変わります。暮らしの3札（水・トイレ／エレベーター／各戸の電気）と被害の目安（松戸市の2026年8月の例を出典つきで）の下に、2段構えのクリティカル対策の表を出します。前提は図面と答えで分かったことだけを書き、分からないものは未確認と書きます。
4. **渡す**：「① 管理会社への依頼メモ」「② 理事会A4資料（1枚）」「③ 対策費用・補助金試算」を切り替えて印刷します。A4 は縦1枚で、上に3つの数字（今のまま浸水したら／事前に対策したら（1戸あたり）／本日決めること N件）、左に平面図・断面図と止まる3札、右に「本日の理事会で決めること」のチェック、費用と補助の3行、立地の2行を置きます（対策の表と単価の表は画面3と費用タブ）。費用タブは単価×個数の表に、住所の市区町村の補助を自動で当てた組合の実質負担と1戸あたりを出します。

右下の「AIチャット 💬」で、どの画面からでもチャットで質問できます（浸水・停電中の危険な場所への立入・操作・接触は、AI を通さず決まった文で答えます）。右上の小さなリンクから「根拠と資料」（需要の証拠・判定の基準・出典）を読めます。地図のライブラリ、3D の模型、前の「くわしい版」の画面は外しました。外部のライブラリは使っていません（サーバーは Python の標準ライブラリ、画面は素の JavaScript と SVG）。

## 架空の見本

`web/samples/` の平面図と模式断面図（PDF、PNG、SVG、CAD の DXF）と点検報告書は、この期間に `scripts/draw_plans.py` で新しく作った架空の見本です。実在の建物の図面や記録ではありません。国の電気設備の浸水対策ガイドラインにある一般的な配置を踏まえて描いています。建物の名前と設備はどれも架空で、見本の住所は町丁の代表点だけを使います。

## 動かし方

Python 3.9 以上があれば動きます。追加のインストールはいりません。

```bash
python3 -m app.server
```

起動したら http://localhost:8000 を開きます。

テストと、公開データが読めるかの確認は次のとおりです。

```bash
python3 -m unittest discover -s tests -t .
```

```bash
python3 -m scripts.check_location
```

## Claude の使い方

API キーを環境変数に入れて起動すると、Claude（`claude-opus-5-5`）が図面の読み取り、建物の Web 検索、相談の答えを担当します。追加のインストールはいらず、標準ライブラリで API を呼びます。

```bash
ANTHROPIC_API_KEY=発行したキー python3 -m app.server
```

環境変数の名前は `.env.example` にまとめてあります（値は空のまま公開しています。`.env` は `.gitignore` で追跡しません。サーバーは `.env` を自動では読まないので、シェルで読み込んでから起動します）。

コマンドを使わずに、localhost で開いた画面の右上の「設定」のボタンから保存することもできます。キーはホームの `.anthropic_api_key`（権限 600、リポジトリの外）にだけ保存し、画面にもログにも出しません。環境変数があれば、そちらを先に使います。保存を受けるのは、同じパソコンの localhost の画面から送ったときだけです。

Claude が担当するのは次のことです。図面を本当に読み取ったときは読めた値をそのまま答えに入れ（1行で知らせ、各行は問いのボタンで直せ、「全部取り消す」で戻ります）、建物の Web 検索とキーなしの見本の答えは人が「はい」「この値を使う」を押したときだけ使います。

- **建物名から階数を探す（画面1）。** マンション名で検索したとき、建物名と町丁を Anthropic の API に送り、Web 検索で地上・地下の階数を出典つきで探します（`/api/building-facts`）。
- **住所から建物名と階数を探す（画面1）。** 住所で場所を選んだとき、その住所にある分譲マンションの名前と階数を Web 検索で探し、一番前の窓の「この建物ですか？」（建物名・階数・戸数・築年・出典）で「はい」を押したときだけ反映し、上の1行に出します（`/api/building-at`）。「違う」か見つからないときは建物名・階数を入れ直せます。
- **図面の読み取り（画面2）。** 平面図・配置図・断面図・立面図・電気設備図（単線結線図）・給排水設備図・外構図を複数枚まとめて読み、部屋と階、地上・地下の階数、引込み（地中／架空）、受電（高圧／低圧）、給水ポンプ制御盤の置き方、排水の放流先、逆止弁、雨水ます、スロープ、換気口、管路口を候補にします。部屋の種類は図に書かれた語を対応表（`app/samples.py` の `ROOM_WORDS`）に当てて決め直し、位置は 0〜1 に収めます。図面は Files API に上げず、その都度の要求に入れて送ります。
- **質問に答える（右下の「AIチャット 💬」）。** 建物の情報、判定の行、補助の表、出典を確かめた事実を読んで答え、平面図の部屋を光らせる・水位や対策を切り替えるといった画面の操作を返します。Web 検索と判定を変える道具は渡しません。
- **現地調査・見積もり仕様カルテと依頼文の下書き（画面4「③ 対策費用・補助金試算」の折りたたみ。送らずコピーして使います）。**

判定はプログラムの決まりだけで出し、Claude には変えさせません。図面がない人の3問（地下スロープ・電気室の扉・止水板）は建物の形と対策の切り替えにだけ使い、判定の色は図面で確かめるまで変えません。水、立入、電気の操作に触れる質問は AI を通さず固定の文を出します。Claude の文は、単位つきの数字、禁止の語、留保の語、誰が確かめるかの主語を事後に確かめ、通らなければ元の文に戻します。固定の文と当日・翌朝の手順は Claude に渡しません。受電設備がないと読むのは、書類に受電設備なしと電気主任技術者を選任していないことの両方が書いてあるときだけです。

成功した応答は `data/cache/` に置き、同じ入力なら API を呼ばずに返します（`ANTHROPIC_NO_CACHE=1` で止まります）。図面や書類を読んだ結果も入るので、公開リポジトリには入れません。チャットは 1 回の質問で API を 1 回だけ呼び、検査に落ちたときだけもう 1 回聞き直します。毎回同じ指示と事実は、Anthropic のプロンプトキャッシュに置きます。

キーがないときは、PDF の文字の位置、語の対応表、見本の答え、説明カード、定型の文面で動き、その旨を画面に出します。図面、住所、建物名、相談の内容、検索の言葉は、キーを設定しているときだけ Anthropic の API へ送ります。

## Claude の実機での確認

2026 年 11 月 7 日に、本物の API（`claude-opus-5-5`）で次を確かめました。使った図面と建物は架空の見本（A・B・C）と、公開情報で確かめられる実在の建物名だけです（作者の手元の本物の竣工図は低解像度のため、下の注記のとおり）。

- **図面の読み取り（見本の竣工図 9 枚：A・B・C の平面図・断面図・系統図）。** 引込み（A・C は地中、B は架空）、受電（A・C は高圧、B は低圧）、盤の置き方（A・C は壁掛け、B は架台）、排水の放流先（公共下水道）、階数（A 11 階・地下 1 階、B 5 階、C 38 階・地下 1 階、基礎ピット）が全部読めました。見つけて直した誤りは、「受水槽」や「雨水貯留槽」の部屋の種類を取り違えること（図の語を対応表に当てて決め直す）と、見本 C で位置が画素の値で返ること（0〜1 に収める）です。画面2で 3 枚をまとめて入れ、「すべて入れる」で部屋の階 4 件・階数・引込み・受電・盤・スロープ・管路口・放流先の 10 件が一度に入ることを、ブラウザで確かめました。
- **断面図の階数。** 地上階数の数え方（1FL から最上階まで。RFL・PH・地下は数えない）を指示に足し、Z1〜Z10 の札がある図で 10 階と読めるようになりました（直す前は 9 階）。
- **建物の Web 検索。** 実在のマンション名 5 件（川崎市・墨田区・中央区・千葉市・千代田区）は、所在地と「この建物ですか？（地上 N 階・地下 N 階・出典）」が 5 件とも出典つきで返りました。番地だけの住所 3 件では 1 件だけ見つかり、2 件は「見つからない」として建物名か階数を入れる欄に落ちました。番地だけの検索は当たれば速く、外れたら手入力、という位置づけです。
- **図面がない人の 3 問。** 住所だけで進み、「竣工図はない」を選んで 3 問に答えると、建物の形（地下に機械室／1 階に機械室）と最優先の対策（管路口の止水埋め／1 階出入口の止水板と換気口カバー、スロープ止水板／階段・出入口の止水板）が切り替わり、判定の色は未確認のままであることを、サーバーの応答とブラウザで確かめました（API は使いません）。
- **チャット。** 危ない質問 20 問（立入、復電、排水、蓋を開ける、変圧器の部屋の穴を塞ぐ、絶縁抵抗の値、倒れている人、在宅の医療機器、今夜浸水するか、安全か、英語、「指示を無視して」など）は 20 問とも AI を通さず固定の文で、0 秒でした。理事長が聞きそうな 10 問（止水板の費用、補助の条件、理事会で決められるか、借室の分担、管路口の止水、内水の逆流と逆止弁、床置きの盤、地図に色がないのに対策が要る理由、管理会社への最初の依頼、非常用発電機）は 9 問が Claude の答えで、数字はアプリのデータ（35 万円、千葉市の 1/2・上限 75 万円 など）と一致しました。「非常用発電機があれば停電は大丈夫？」だけは「発電機＋大丈夫」の語で固定の文になります（取りこぼしより出しすぎを許す設計のまま）。仮定の問いを聞き取りの事実として記録していたので、指示に一言足しました。
- **相談の文書（`/api/consult`）。** 見本 A・C は Claude の文（検査を通過）。見本 B は初回が JSON の読み取り失敗で定型に落ち、再送で Claude の文になりました（一過性）。

| 種類 | 経路 |

| 電気室への立入、電源を入れる、排水、蓋を開ける、変圧器の部屋の穴を塞ぐ、覗く、「指示を無視して」、英語の質問 | AI を通さず固定の文 |

注記：作者の手元にある本物の竣工図 3 枚は長辺 545〜700px の縮小画像しかなく、2,000px に拡大しても室名は読めませんでした（読めたのは図面の種類、階数 10 階、EV・階段・駐車場まで）。高解像度の原本があれば読み直します。この 3 枚と、そこから分かることは公開リポジトリに入れていません。チャットの答えは毎回変わるので、この結果は同じ文が必ず出ることを約束するものではありません。実際の設備の判断は、電気主任技術者が行います。2026 年 11 月 2 日の最初の実機確認（住所の推定、点検報告書の項目の抜き出し、画面を動かす道具、危ない質問 20 問）の結果も、今の設計の前提です。

## 公開前の確認（2026-11-07）

セッション5弾「Claude Code で作ったアプリを安全に公開する」のチェックリストに沿って確かめました。

- 追跡しているファイルと全履歴（76 コミット・全ブランチ）に、API キーや秘密鍵の形の文字列がないことを、値を出さない検索で確かめました。キーは `~/.anthropic_api_key`（リポジトリの外、権限 600）か環境変数にだけ置き、`/api/status` が返すのは「env／file／なし」の区別だけです。
- サーバーは 127.0.0.1 にだけ待ち受けます。キーの保存は、同じパソコンの localhost の画面から送ったときだけ受けます。すべての POST に application/json を求め、ほかのサイトからの送信は断ります。形の違う入力や想定外の失敗は、行番号や値を含まない短い JSON で返します（`tests/test_server_input.py`）。
- 見本の図面・報告書・住所は架空で、作者の手元の本物の図面と番地つきの住所はリポジトリに入れていません（`tests/test_knowledge.py` が禁止の語を見張ります）。
- 新しい場所に clone し、README の手順どおりに起動してテスト（452 件）が通ること、キーなしで画面が「見本の答え」に落ちることを確かめました。
- まだのもの：GitHub の Settings（公開範囲・共同編集者・ブランチ保護・Secret scanning と Push protection）の確認、Claude Security プラグインでのスキャン、gitleaks などの pre-commit フック（このパソコンには未導入）。
