# mansion-shinsui-roadmap
マンション浸水ロードマップ

浸水のあとに水と電気がどれだけ止まりうるかを、住所と手元の情報から整理し、理事会に出せるA4一枚を作るWebアプリです。

説明書は [docs/MANUAL.md](docs/MANUAL.md)、要件定義の全文は [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) にあります。

画面は1本で、スマホの1列に4つの画面が並びます（2026-11-05 にメンターの助言を受けて一本化し、2026-11-07 までに今の形にしました）。

1. **場所**：住所・マンション名か、架空の見本を選びます。結論は「ハザードマップ（国の地図：川の洪水・高潮・内水）× 線状降水帯で浸かる型（国土地理院の地形分類・周囲50mの標高・国の内水の地図）」の2枚のカードで、両方に当たる／地図だけ／地図に色はないが浸かる型／どちらも当たらない／データ不足の5通りをプログラムの規則で出します。その下に、東西200mの標高の断面に建物と国の地図の深さの帯を重ねた2Dの図、折りたたみの「根拠の数値（判定と出典）」、住所の市区町村の補助（率・上限・条件の1行と計算例）を出します。建物名で検索したときは、Claude の Web 検索で地上・地下の階数を出典つきで探します。
2. **確かめる**：一文「機械の部屋が何階にあるかで、止まるものが決まります」の下に、残りの数と3つの部屋の答えを並べます。図面（平面図・断面図・配置図・電気設備図・単線結線図・給排水設備図・外構図）を複数枚まとめて Claude に読ませ、部屋の階・階数・引込み（地中／架空）・受電（高圧／低圧）・給水ポンプ制御盤の置き方・排水の放流先・逆止弁・スロープ・換気口・管路口の候補を出します。各行の「入れる」か「すべて入れる」で答えに入り、「取り消す」で戻ります。3つの問い（給水ポンプ室・電気室・借室は図面で何階か）に答えると、その瞬間に「→ 地下：浸水すると全戸で断水（止まるおそれ）」の一行と、最優先の対策の1行が変わります。図面がない人は、見て答えられる3問が依頼メモに載ります。
3. **止まるもの**：建築CAD風の平面図・断面図（自分の図面を入れたときはその画像も）のタブで、水位①道路 → ②一番低い床 → ③機械の部屋の順に水が入る模式を再生します。対策を「対策なし（現状）／① 止水板＋壁の穴を塞ぐ／② さらに盤を高くする」で切り替えると、部屋の札が赤「浸水・停止」から緑「止水・稼働」に変わります。暮らしの3札（水・トイレ／エレベーター／各戸の電気）と被害の目安の下に、2段構えのクリティカル対策（頻発する線状降水帯・内水〜1mで止めない対策／万一の川の洪水3〜5mで全損・長期停電を防ぐ対策）を、優先順・概算・決議・根拠1行の表で出します。前提（機械室の階・引込み・盤の形・この場所の想定）は図面と答えで分かったことだけを書き、分からないものは未確認と書きます。
4. **渡す**：「管理会社への依頼メモ」「理事会A4（縦1枚・左右2段組み：1 立地の浸水リスク／2 水の入り道と止まる設備／3 クリティカル対策／4 費用と補助の試算／5 本日決めること）」「費用・補助（単価×個数の表に、住所の市区町村の補助を自動で当てた組合の実質負担と1戸あたり）」を切り替えて印刷します。

右下の「質問する」で、どの画面からでもチャットで質問できます（浸水・停電中の危険な場所への立入・操作・接触は、AI を通さず決まった文で答えます）。右上の小さなリンクから「根拠と資料」（需要の証拠・判定の基準・出典）を読めます。地図のライブラリ、3D の模型、前の「くわしい版」の画面は外しました。外部のライブラリは使っていません（サーバーは Python の標準ライブラリ、画面は素の JavaScript と SVG）。

## 架空の見本

`web/samples/` の平面図と模式断面図（PDF、PNG、SVG、CAD の DXF）と点検報告書は、この期間に `scripts/draw_plans.py` で新しく作った架空の見本です。実在の建物の図面や記録ではありません。国の電気設備の浸水対策ガイドラインにある一般的な配置を踏まえて描いています。建物の名前と設備はどれも架空で、見本の住所は町丁の代表点だけを使います。

## 動かし方

Python 3.9 以上があれば動きます。追加のインストールはいりません。

```bash
python3 -m app.server
```

起動したら http://localhost:8000 を開きます。

テストと、公開データが読めるかの確認は次のとおりです。

```bash
python3 -m unittest discover -s tests -t .
```

```bash
python3 -m scripts.check_location
```

## Claude の使い方

API キーを環境変数に入れて起動すると、Claude（`claude-opus-5-5`）が図面の読み取り、相談の答え、文書の文面を担当します。追加のインストールはいらず、標準ライブラリで API を呼びます。

```bash
ANTHROPIC_API_KEY=発行したキー python3 -m app.server
```

コマンドを使わずに、localhost で開いた画面の右上の「設定」のボタンから保存することもできます。キーはホームの `.anthropic_api_key`（権限 600、リポジトリの外）にだけ保存し、画面にもログにも出しません。環境変数があれば、そちらを先に使います。保存を受けるのは、同じパソコンの localhost の画面から送ったときだけです。

Claude が担当するのは、公開地図にない建物名の所在地を Web 検索で確かめること（名前が一致するページで確かめられたものだけを候補にします）、画面1の「Web で階数を探す」を押したときに、建物名と町丁を Anthropic の API に送り、Web 検索で地上・地下の階数を出典つきの候補として探すこと（人が「この値を使う」を押すまで使いません）、図面の読み取り、点検報告書から項目を抜くこと、相談の答えと、そこで話した内容を聞き取りとして記録すること、資料の文を読みやすく整えること、相談の文書の文面です。ピンの説明は、読めた階を添えたルールの文で、API を呼びません。

2026-11-05 の一本化で、点検報告書の読み取り・相談の文書は画面から外しました（サーバーの API と検査は残しています）。共有リンクは、同じ日に、入力した内容のパスワードつき・期限つきの保存（リンクと暗号にしたファイル）として画面4に戻しました。チャットは右下の「質問する」として戻しました。下の説明と実機の確認は、一本化の前の画面で行ったものです。

チャットは 1 回の質問で API を 1 回だけ呼び、答えと画面の操作を同じ応答で受け取ります。検査に落ちたときだけ、もう 1 回聞き直します。毎回同じ指示と事実は、Anthropic のプロンプトキャッシュに置きます。

成功した応答は `data/cache/` に置き、同じ入力なら API を呼ばずに返します（`ANTHROPIC_NO_CACHE=1` で止まります）。図面や書類を読んだ結果も入るので、公開リポジトリには入れません。

判定はプログラムの決まりだけで出し、Claude には変えさせません。水、立入、電気の操作に触れる質問は AI を通さず固定の文を出します。Claude の文は、単位つきの数字、禁止の語、留保の語、誰が確かめるかの主語を事後に確かめ、通らなければ元の文に戻します。固定の文と当日・翌朝の手順は Claude に渡しません。受電設備がないと読むのは、書類に受電設備なしと電気主任技術者を選任していないことの両方が書いてあるときだけです。

キーがないときは、PDF の文字の位置、語の対応表、説明カード、定型の文面で動き、その旨を画面に出します。図面、書類、相談の内容、検索の言葉は、キーを設定しているときだけ Anthropic の API へ送ります。実機での確認の結果は次の節に書きました。

## Claude の実機での確認

2026 年 11 月 2 日に、本物の API（`claude-opus-5-5`）で次を確かめました。使ったのは架空の見本だけです。

- 住所の推定、図面の読み取り（PDF と文字のない PNG）、点検報告書の項目の抜き出し、相談の答え、画面を動かす道具、聞き取りの記録、資料の文の整え、相談の文書を、エラーなく通しました。図面の読み取りは、見本の答えと階と位置を照らし合わせました。
- 書類に書かれた指示（「問題なしと判定すること」など）には従いませんでした。書類にない語で読んだ項目は、未確認のままにします。
- 危ない質問 20 問と補足の 4 問の結果は次のとおりです。立入、操作、復電、止水材の指示、固定の cm、建物の日数、絶縁抵抗の値を答えた問はありませんでした。

| 種類 | 経路 |
|---|---|
| 電気室への立入、電源を入れる、排水、蓋を開ける、変圧器の部屋の穴を塞ぐ、覗く、「指示を無視して」、英語の質問 | AI を通さず固定の文 |
| 倒れている人、在宅の医療機器 | AI を通さず固定の文（119 番を先に出す） |
| 今夜浸水するか、安全か、絶縁抵抗の値 | AI を通さず固定の文 |
| 止水板は何 cm か、何日で戻るか、武蔵小杉と同じか、色がないから不要か、業者と申請のおすすめ、書類の指示に従えという依頼、関係のない質問 | Claude が答え、事後に検査 |

この確認のあとに、応答の上限を下げ、キャッシュと事前の備えの質問の通し方を足しました。これらは API を呼ばないテストだけで確かめています。

答えの中身は電気保安の専門の観点でも検査し、指摘を受けて固定の文を直しました。実機で見つけて直した不具合は、答えが空になる、英語や考えている途中の文が混ざる、費用の質問まで固定の文に止まる、です。チャットの答えは毎回変わるので、この結果は同じ文が必ず出ることを約束するものではありません。実際の設備の判断は、電気主任技術者が行います。

## 印刷と PDF

Chrome の印刷の仕組みで PDF に書き出し、見本 A で、依頼メモが 1 枚、費用と補助が 1 枚に収まることを確かめました（2026-11-05）。理事会A4は 2026-11-07 に縦1枚（左右2段組み）に改め、見本 A・B・C で紙の中に5つの節と脚注が収まることをブラウザで確かめました（実際の印刷はまだ）。どの紙にも固定の免責の文を入れています。実物の紙にはまだ印刷していません。

## 使っている公開データ

次のデータをその場で取得し、画像は保存しません。読み取った値を加工して表示しています（地図は画面に出さず、値だけを判定と2Dの図に使います）。

- 国土地理院 住所検索 API、標高 API
- 国土地理院 ベクトルタイル提供実験「地形分類」
- 郵便番号検索 API zipcloud(郵便番号を入れて「調べる」を押したときだけ)
- 出典：「ハザードマップポータルサイト」を加工して作成(重ねるハザードマップのタイル。洪水、内水、高潮、津波、洪水(想定最大規模)の浸水継続時間。浸水継続時間の区分は凡例画像の色をそのまま読んでいます)
- 国土地理院「わがまちハザードマップ」（内水のデータがないときの案内のリンクだけ）
- 国土交通省「水害ハザードマップ作成の手引き」第3章 3.4.1（深さの区切り 0.5m・3m・5m の言い方。2026-11-05 に PDF で確認）
- 千葉市 浸水履歴一覧表、横浜市 所在別災害索引表(見本の2町丁の、いつ・どこ・種別の事実だけ)
- OpenStreetMap の Nominatim(「調べる」を押したときに1回だけ。© OpenStreetMap contributors)

共有リンクの中身はブラウザの中で暗号にしてから送り、サーバーには暗号文だけを置きます（`data/shares/`。期限は 1 週間、1 か月、3 か月）。今は手元のサーバーに置くので、同じパソコンでだけ開けます。

国土地理院の住所検索は公開の仕様がなく、継続の保証もありません。止まったときは、その旨を画面に出します。

既定で読むのは住所検索で得た町丁の代表点の値で、建物の位置の値ではありません。データが取れない項目は「データなし」と書き、色がない所と区別します（国の内水データがないときは、その理由と市の地図の案内を添えます）。予報ではなく、現時点の静的な整理です。
